Planning a complete Vite and Three.js application.

The plan covers 11 features: binary data preprocessing, a Kepler solver, InstancedMesh for 42,000 asteroids, time controls, filtering, detail views, PHA highlighting, comets, Sentry risk, focus camera, and shareable URLs. Performance targets 1–2 ms per frame for 42,000 objects via Float32Array packing and lightweight CPU-side Kepler solving.

Writing the Kepler solver now. It uses the Gaussian constant K and a fast iterative elliptic solver with 12 steps and early exit. True anomaly conversion follows.

The `position` function computes true anomaly and radial distance. It branches by eccentricity: low-eccentricity ellipses, high-eccentricity ellipses, and parabolic trajectories.

Parabolic trajectories use Barker’s equation. Hyperbolic orbits solve M = e sinh H − H. Cartesian coordinates convert from perifocal to ecliptic using the argument of periapsis, inclination, and longitude of ascending node.

Camera range spans 0.5 to 50 AU. Real solar system radii collapse to near-zero units at this scale, so planet sizes will be artificially inflated. The Sun will render at roughly 0.05–0.08 AU visually.

Planets will scale proportionally from Earth at roughly 0.015 AU. Asteroids will appear as instanced spheres sized by diameter or absolute magnitude, with PHAs highlighted in orange and red. Orbit trails will be rendered as sampled Line loops for individual bodies, avoiding the full 42,000 trail set. Date conversion will map Unix timestamps to Julian dates, anchored to the 2026 August 12 epoch. URL state will encode time, selected object, camera settings, and active filters.

The build pipeline will use a Vite plugin or standalone script to preprocess data at build time. Asteroids will be packed into a compact Float32Array binary file containing eight orbital parameters per object, plus a small metadata JSON. Comets will be packed with extra flags for hyperbolic trajectories. Close approaches will be indexed by designation and stored in a compact JSON grouped by DES, keeping only upcoming or recent entries for the list while retaining all records for the selected object.

Close approaches will be stored as a map from designation to an array of structured records. The packed orbit binary will be roughly 1.35 MB, and the metadata JSON about 2–3 MB. The metadata schema will use typed arrays for compactness: strings for designations and names, uint8 for class and flags, float32 for H, diameter, and MOID, and uint32 for SPKIDs.

The application will use a minimal custom UI styled after NASA, avoiding extra libraries. Source files will be split into orbit, scene, UI, time, state, and style modules. Vite will be configured with `base: './'`, disabled public directory, and a prebuild step that copies packed data into `public/packed/` so Vite copies it to `dist`.

Runtime will fetch packed data from `dist/data/`. The original `data/` folder stays read-only. A prebuild script will pack the raw JSON into the `dist` output during `pnpm build`.
